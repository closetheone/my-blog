## 2. 产品概述

### 2.1 产品定位

一句话定位：**以个人博客为载体的全栈开发学习项目** —— 既是内容阵地，也是一条完整走过「前端 → 后端 → 数据库 → 认证 → 部署运维」的学习路径。

定位关键词：`个人` `内容` `学习` `长期主义`

产品形态：Web 网站（响应式，移动端优先），单作者多读者模式，动态架构（自有后端 + 数据库）。

### 2.2 双重目标

本项目同时服务两个目标，功能取舍时按此权衡：

| 目标 | 说明 |
| --- | --- |
| **内容目标** | 一个好用的个人博客：写作高效、阅读舒适、可被搜索 |
| **学习目标** | 走完全栈开发与部署的完整流程，技术选型以主流、可迁移为准，不为省事牺牲学习价值 |

### 2.3 学习目标（衡量学习成果）

| 阶段 | 技术能力 | 验证方式 |
| --- | --- | --- |
| 前端 | React / Next.js / Tailwind CSS / 响应式 / SEO | 完成博客前台全部页面 |
| 后端 | API 设计 / Node.js 服务端逻辑 / 文件上传 | 完成管理后台与评论接口 |
| 数据库 | PostgreSQL 表设计 / ORM / 数据迁移 | 文章、评论、点赞全部入库 |
| 认证 | 会话管理 / 密码哈希 / CSRF 防护 | 管理员登录系统上线 |
| 部署运维 | Linux / Docker / Nginx / HTTPS / CI/CD / 备份 | 站点部署至自有 VPS 并稳定运行 |

### 2.4 用户角色

| 角色 | 描述 | 核心诉求 |
| --- | --- | --- |
| 博主（管理员） | 唯一内容生产者，即本人；通过账号密码登录后台 | 写作高效、管理轻松、掌握全部技术细节 |
| 读者 | 通过搜索、分享、友链而来的访客，**无需注册** | 快速找到内容、舒服阅读、低门槛互动 |

> 模式为「单管理员 + 匿名读者」：仅博主需要登录，读者互动（评论/点赞）零门槛。读者注册体系明确不做（见 §9）。

## 4. 信息架构（站点地图）

```

├── 首页（个人简介 + 置顶文章 + 文字流文章列表）

├── 登录页
├── 仪表盘（数据概览）
├── 文章管理（列表 / 新建 / 编辑）
├── 图片管理
├── 评论管理
```

**全局元素**：顶部导航栏（站名 + 主导航 + 搜索入口 + 暗色模式切换）、阅读进度条（文章页）、页脚（版权 + 运行天数 + RSS + 社交链接）。

## 5. 功能需求

> 优先级定义：
> - **P0**：该版本必须，缺失则产品不成立
> - **P1**：重要，紧随其后交付
> - **P2**：增值功能，视情况排期
>
> 优先级对应版本落点见 §8 版本规划。

### 5.0 核心数据实体

系统管理以下数据实体（详细表结构在技术设计阶段确定）：

`管理员账号` `文章` `分类` `标签` `评论` `点赞` `留言` `图片资源`

### 5.1 模块 M1：文章展示（前台）

| 编号 | 功能 | 优先级 | 需求描述 |
| --- | --- | --- | --- |
| FR-1-01 | 文章列表 | P0 | **文字流布局**（决策 D-06）：每条展示标题、摘要、发布日期、标签，无封面图（单篇可选配封面为 P2 灵活项，用于游记/摄影类随笔）；首页顶部为博主一句话简介 + 社交链接；每页 10 条，分页加载 |
| FR-1-02 | 文章详情 | P0 | Markdown 渲染；代码块语法高亮 + 行号；展示发布时间（完整日期）、字数、预计阅读时长（按 400 字/分钟） |
| FR-1-03 | 草稿/发布状态 | P0 | 文章分「草稿 / 已发布 / 隐藏」三种状态；仅「已发布」对外可见 |
| FR-1-04 | 上一篇/下一篇 | P1 | 文章底部展示相邻两篇已发布文章，可点击跳转 |
| FR-1-05 | 置顶 | P1 | 可将文章置顶于首页顶部，最多 3 篇，置顶有 📌 视觉标识 |
| FR-1-06 | 文章目录（TOC） | P1 | 桌面端右侧两级标题目录，滚动高亮当前章节；移动端折叠为顶部展开式 |
| FR-1-07 | 系列文章 | P2 | 多篇文章归属同一系列，详情页顶部展示系列导航 |
| FR-1-08 | 多媒体支持 | P1 | 图片懒加载 + 点击放大（灯箱）+ 图注；视频/音乐外部嵌入；P2 增加数学公式渲染 |
| FR-1-09 | 阅读体验规格 | P1 | 见 5.9 全局体验中的排版规格，随文章详情页一并验收 |

**FR-1-02 验收标准：**
1. Markdown 标题、列表、表格、引用、链接、图片正确渲染
2. 常见语言代码块高亮正确，右上角有语言标签 + 复制按钮
3. 无脚本执行风险（Markdown 中 HTML 白名单过滤）
4. 正文内外部链接在新窗口打开

### 5.2 模块 M2：内容组织（前台）

| 编号 | 功能 | 优先级 | 需求描述 |
| --- | --- | --- | --- |
| FR-2-01 | 分类 | P0 | 树形结构（最多两级）；一篇文章仅属于一个分类；展示分类下文章数；**全站分类总数硬性上限 8 个**。初始分类（基于「技术 + 生活随笔」定位）：`技术`（子分类：前端 / 后端 / 工具与效率）、`生活随笔`、`读书笔记`、`折腾记录` |
| FR-2-02 | 标签 | P0 | 平铺结构，一篇文章可挂多个标签（建议 ≤ 5 个）；提供全部标签聚合页；**防碎片纪律：后台标签输入采用「从已有标签中选择 + 搜索不到再新建」的交互，杜绝 `Redis`/`redis` 类重复标签** |
| FR-2-03 | 归档 | P1 | 纯文字时间线，每行「日期 + 标题（+ 评论数）」，按年份分组，年份可折叠 |
| FR-2-04 | 相关推荐 | P2 | 文章底部展示「相关文章」（按共同标签匹配，最多 3 篇） |

**FR-2-01 验收标准：** 删除分类时需提示处理其下文章（移入未分类或二次确认），不允许出现死链。

### 5.3 模块 M3：互动（自建，读者零注册）

| 编号 | 功能 | 优先级 | 需求描述 |
| --- | --- | --- | --- |
| FR-3-01 | 评论 | P1 | 文章底部评论区（读完正文出现或点击展开，不打断阅读）；**正序展示**（如对话从头读起）；层级回复最多两级，更深层用「@昵称」表示；读者填昵称 + 邮箱（**永不公开显示**，仅用于头像与通知）即可评论，个人网址选填 |
| FR-3-02 | 评论管理 | P1 | 博主可在后台删除/置顶评论；反垃圾：单 IP 频率限制（1 条/分钟）+ 敏感词过滤 + 评论内容 XSS 过滤 |
| FR-3-03 | 点赞 | P2 | 文章点赞按钮；**点赞数公开展示**（决策 D-09）；同一访客对同一文章仅一次（本地去重 + 服务端校验，不追求强一致） |
| FR-3-04 | 留言板 | P2 | 独立页面，不隶属任何文章，供访客自由留言；复用评论的数据结构与反垃圾逻辑；**不做先审后发**（实时可见 + 反垃圾规则，个人博客量级优先保护留言热情） |
| FR-3-05 | 浏览量 | P1 | 单文章 PV 计数展示；按 IP+文章维度去重（时间窗口内） |
| FR-3-06 | 单篇评论开关 | P1 | 每篇文章有「允许评论」开关（默认开）；关闭时评论区显示「本文已关闭评论」 |
| FR-3-07 | 评论头像 | P1 | 邮箱关联 Gravatar；无头像时按邮箱哈希生成随机几何头像（不用灰色占位块） |
| FR-3-08 | 邮件通知 | P2 | 评论框提供「有人回复我时邮件通知」勾选框（默认勾选）。**缓期至 V3.x**（决策 D-07）：邮件送达涉及 SPF/DKIM 配置与送达率，是独立的学习点 |

> 与 V1.0 的变更说明：原方案为第三方 Giscus，因学习目标改为自建评论系统——评论是练手后端的最佳载体（完整的 CRUD + 反垃圾 + 管理后台）。读者侧体验反而更好（无需 GitHub 账号）。

### 5.9 模块 M9：全局体验（排版规格与产品基调）

**排版规格（随文章详情页验收）：**

| 项目 | 规格 |
| --- | --- |
| 正文字号/行高 | 16–17px / 行高约 1.8 |
| 内容宽度 | 窄栏约 700px（一行 40 字左右），不全宽 |
| 阅读进度条 | 文章页顶部 2px 细条，随滚动前进 |
| 代码块 | 语法高亮 + 行号 + 语言标签 + 右上角复制按钮 |
| 图片 | 懒加载、点击灯箱放大、支持图注 |
| 外链 | 正文内外部链接新窗口打开 |

| 项目 | 要求 | 优先级 |

## 8. 版本规划（渐进式学习路径）

> 每个版本交付后都是一个**可上线的完整站点**，学习不停机。技术栈贯穿始终：Next.js（全栈框架）+ PostgreSQL + TypeScript。

| 版本 | 交付内容 | 版本目标 | 对应学习目标 |
| --- | --- | --- | --- |
| **V1.0** | Next.js + Tailwind 前台；文章以 Markdown 文件管理；文字流首页 + 排版规格（M9）；暗色模式；SEO 基础；部署到 Vercel（免费） | 能写、能看、能被搜到；快速看到成果 | React / Next.js / Tailwind / Git 工作流 / 托管平台部署 |
| **V1.1** | 搜索、归档、RSS、TOC、置顶、上一篇/下一篇、404 页（含随机文章）、复制链接分享 | 内容规模化后依然好用 | 前端进阶：性能、SEO、可访问性 |
| **V2.0** | PostgreSQL + Prisma；管理员登录（FR-6-01/02）；浏览器内 Markdown 编辑器与文章管理（FR-6-03/04/09/11）；内容迁移入库 | 摆脱本地写文件，全后台管理 | **数据库设计与 ORM / 认证与会话 / 密码安全 / API 设计** |
| **V2.1** | 评论 + 评论管理（含 Gravatar、单篇开关）、点赞、浏览量、仪表盘（FR-3-01~07、6-08） | 与读者建立连接 | **XSS/CSRF 防护 / 限流防刷 / 缓存** |
| **V3.0** | 购买 VPS，Docker + Nginx + HTTPS 迁移自托管；CI/CD；备份；监控（M8 全模块） | 完整掌控生产环境 | **Linux 运维 / 容器化 / 反向代理 / 自动化部署 / 生产安全** |
| **V3.x** | 留言板、友链、系列文章、相关推荐、分享卡片、定时发布、**邮件通知（FR-3-08）**、文章版本历史 | 体验打磨 | 综合练习 + 按兴趣延伸（邮件送达是独立学习点） |

> V1.0 先部署 Vercel 的原因：最快看到上线成果、免费、零运维，先把前端基础打牢；V3.0 再迁移自有 VPS 完成运维学习。若希望更早接触 Linux，可提前 V3.0。
